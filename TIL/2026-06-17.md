## 비대화형 환경에서 git 자격증명 프롬프트로 인한 클론 실패

**배운 것**
Claude Code 같은 비대화형 셸에서 git 클론이 실패할 때, 원인이 "권한 없음"이 아니라 "자격증명 입력 프롬프트를 띄울 수 없음"인 경우가 있다. 저장소가 공개여도 발생할 수 있다.

**핵심 내용**
- `claude plugin marketplace add <repo>` 실행 시 `fatal: Cannot prompt because user interactivity has been disabled` / `unable to get password from user` 에러로 실패.
- 저장소가 공개인지 먼저 확인: `git ls-remote <url>` 가 익명으로 성공하면 접근 자체는 문제없음 → 진짜 원인은 git 자격증명 프롬프트.
- Windows Git Credential Manager(GCM)가 자격증명을 주입하려고 프롬프트를 띄우는데, 비대화형이라 막혀서 실패한 것.
- 해결: 프롬프트를 끄고 익명 클론을 강제한다.
  - `GIT_TERMINAL_PROMPT=0` — git 자체 터미널 프롬프트 비활성화
  - `GCM_INTERACTIVE=never` — Git Credential Manager 대화형 비활성화

**예시 / 코드**
```bash
# 1) 공개 여부 확인 (익명 접근 성공하면 OK)
git ls-remote https://github.com/Cloudlab-WT/cloudlab-plugins.git

# 2) 남은 임시 폴더 정리 후, 프롬프트 끄고 재시도
rm -rf "C:/Users/<user>/.claude/plugins/marketplaces/temp_"*
GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never \
  claude plugin marketplace add https://github.com/Cloudlab-WT/cloudlab-plugins.git
```

**더 알아볼 것**
- git credential helper 설정(`git config --global credential.helper`) 확인 및 환경별 전략

## ims MCP 플러그인으로 개발 서버 재시작

**배운 것**
ims MCP 도구를 통해 셸 명령 없이 카탈로그의 service_id 기반으로 인프라 서비스를 재시작할 수 있다. dev/prod 안전 프로토콜이 도구 레벨에 내장되어 있다.

**핵심 내용**
- 흐름: `list_services`(자연어 → 정확한 service_id 매칭) → `restart_service` → 15~30초 후 `get_restart_status`.
- "개발 외부 API 서버" → `saas-api-dev` 로 매칭 (name_ko/name_en/aliases 대조).
- dev 서비스는 `confirm=False`로 즉시 재시작. prod 서비스는 `confirm=True` 없이는 서버가 거부 → 사용자 명시 승인 필수.
- 결과 확인: `get_restart_status` → `Success`, 컨테이너가 Restarting → Started 로 기동되면 정상.

**예시 / 코드**
```
list_services(env="dev") → saas-api-dev (외부 API)
restart_service(service_id="saas-api-dev")  # dev라 confirm 불필요
  → {status: "submitted", command_id: "..."}
get_restart_status(command_id, service_id) → {status: "Success"}
```

**더 알아볼 것**
- prod 서비스 재시작 시 confirm=True 승인 흐름 실제 동작
- 플러그인 설치 후 `/reload-plugins`, `/mcp` 로 MCP 서버 인증/연결하는 과정
