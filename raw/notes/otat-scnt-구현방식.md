# 상시·수시위험성평가 SCNT 표준승인 — 구현 방식 공유

> **마일스톤**: [ATMS26-012] 한화오션(주) 상시·수시위험성평가 승인모듈 기능 추가
> **작성**: 2026-07-20 / 이찬호
> **목적**: 구현 방향 설명용. 대면 설명 전에 훑어보시면 됩니다.

---

## 1. 한 줄 요약

수시위험성평가의 **자체 승인 로직**(`STTS_CD` 30/40/50/60 + 공사팀장/안전팀장/현장소장 고정 3단계)을
**SCNT 표준 승인관리**로 대체하고, 다른 모듈도 붙일 수 있는 **재사용 표준**을 함께 세웁니다.

기존 방식의 근본 문제는 **승인선이 3단계로 하드코딩**돼 있다는 점입니다.
회사마다 결재 라인이 다른데 컬럼(`APPRV_C/BD/A_USER_NO`)이 3개로 고정돼 있어 확장이 안 됩니다.
SCNT는 승인라인을 데이터로 관리하므로 이 제약이 사라집니다.

---

## 2. 핵심 설계 — 옵션으로 두 엔진을 가른다

### 2.1 상호배타 구조

| 상태 | `SFAS_OPT_060` | `SFAS_OPT_060_003` |
|---|---|---|
| 기존 결재 사용 | `T` | `F` |
| **SCNT 표준승인 사용** | **`F`** | `T` |
| 승인 미사용 | `F` | `F` |

- `060` = **기존 결재 엔진** on/off (의미 그대로 유지)
- `060_003` = **NEW 승인(SCNT)** 사용여부 (신규)
- **둘 다 `T`는 불가** — admin UI에서 양방향 잠금으로 원천 차단

### 2.2 ⚠️ 이 설계의 대가 (가장 주의할 점)

SCNT 현장은 **`060 = F`로 저장**됩니다.
그래서 `060='T'`를 **"승인 활성"** 으로 읽는 기존 SQL이 SCNT 현장을 **"승인 없음"으로 오판**합니다.

```sql
-- 약 15~20 파일 / 40여 조건절을 일괄 수정해야 함
SFAS_OPT_060 = 'T'  →  (SFAS_OPT_060 = 'T' Or SFAS_OPT_060_003 = 'T')
SFAS_OPT_060 = 'F'  →  (SFAS_OPT_060 = 'F' And SFAS_OPT_060_003 = 'F')
```

빠뜨리면 **미승인 건이 목록에 노출되거나 상태 라벨이 공백**이 됩니다.

---

## 2.5 옵션을 바꾸면 기존 회차는 어떻게 되나 (소급 유지) ✅ 적용 완료

> 실무에서 가장 많이 물어보실 부분이라 따로 정리했습니다.

### 결론부터 — 기존 회차는 건드리지 않습니다

기존 결재(060)를 쓰다가 SCNT(060_003)로 바꿔도, **이미 만들어진 회차는 원래 방식 그대로** 굴러갑니다.
옵션 변경 시점 **이후에 새로 만든 회차부터** SCNT로 진행됩니다.

| | 옵션 변경 전에 만든 회차 | 변경 후에 만든 회차 |
|---|---|---|
| 결재 방식 | **기존 결재 그대로** | SCNT 표준승인 |
| 상태 표시 | `공사팀장승인대기` 등 기존 문구 | `승인대기` 등 SCNT 문구 |
| 승인 버튼 | **그대로 뜸** | 승인 팝업에서 처리 |

즉 **한 화면에 두 방식이 섞여** 보입니다. 회차마다 자기가 시작한 방식으로 끝까지 갑니다.

### 왜 이렇게 했나

옵션을 바꾸는 순간 전부 SCNT로 갈아엎으면, 안전팀장 승인을 기다리던 회차가 기존 버튼은 사라지고 SCNT로는 아직 요청도 안 된 상태가 되어 **승인도 취소도 못 하고 멈춥니다**. 승인 이력은 감사 성격이라 나중에 바뀌면 곤란하기도 합니다. 그래서 **진행 중이던 건은 절대 끊기지 않게** 하는 쪽을 택했습니다(옵션 되돌려도 동일).

### 화면에서 보이는 상태값 (SCNT 회차)

| 상태 | 언제 |
|---|---|
| 작성중 | 아직 승인라인을 만들지 않음 |
| 요청대기 | 승인라인은 저장했고, 승인요청 전 |
| 승인대기 | 승인요청함 |
| 승인중 | 결재가 중간 단계까지 진행됨 |
| 승인반려 | 반려됨 |
| 승인완료 | 최종 승인됨 |

기존 결재 회차는 예전 문구(`공사팀장승인대기` 등)를 유지. 상태 옆 **단계 / 대기자** 두 컬럼으로 현재 단계·차례를 표시(기존 결재 회차는 빈칸).

승인 팝업은 **SCNT 회차의 상태값 클릭** 시 열림. 기존 결재 회차는 예전처럼 목록 승인 버튼으로 처리.

## 3. 데이터 구조

### 3.1 호스트 테이블 `TSF_ASSMNT_RECEIVE` (컬럼 4개 추가 — 반영 완료)

| 컬럼 | 타입 | 용도 |
|---|---|---|
| `CFM_COMPANY_ID` | `NUMBER` | SCNT 승인요청 링크 |
| `CFM_PROJ_CODE` | `VARCHAR2(30)` | 〃 |
| `CFM_DEM_SN` | `NUMBER` | 〃 |
| `CFM_STS_CODE` | `VARCHAR2(10)` | **승인상태 캐시** |

**기존 `STTS_CD`는 그대로 둡니다.** 컷오버가 현장별이라 한 현장에 구/신 데이터가 공존하므로 한 컬럼에 합치면 구분이 안 됩니다.

### 3.2 `CFM_STS_CODE` — SCNT 코드를 그대로 복사

숫자 번역 없이 `TBASE_SANCTN_DEM.STS_CODE` 값을 그대로 씁니다. 공통코드 `SANCTN_STS_CODE` 표시명: REG=작성중 · DEM=승인대기 · PROG=승인중 · REJ=승인반려 · CMPL=승인완료. Handler가 복사만 하면 되어 틀릴 여지가 없고, 표시명은 `SF_GetCommonCodeName()`이 처리합니다. (화면에선 REG를 "요청대기"로 override)

### 3.3 저장 vs 조회 구분

- 상태(`CFM_STS_CODE`) + DEM 링크 3키 → **호스트에 저장**(Handler write)
- 승인단계명·대기자 → **저장 안 함**, 조회 시 SCNT에서 주입 (이중 소유 방지, CESC·DCMT 동일)

## 4. 화면 구성

### 4.1 외곽 목록 `SfasRegAtRiskasmtRcpt`

`060_003=T`면 승인 관련 컬럼을 세트 단위로 교대: `[기존] 상태|공사팀장|안전팀장|현장소장` → `[SCNT] 상태|단계|대기자`. 목록 화면이라 행마다 SCNT 조회하면 N+1 → 키를 모아 `selectSanctionDemandMap()` 1회 호출 후 메모리 병합(CESC의 행별 N+1은 안 따름).

### 4.2 승인 팝업 `SfasPopRegRiskAssessmentConfirm` (신규)

상태 컬럼 클릭 시 열림. 조회 전용, 승인 액션은 승인패널 wframe이 담당. 상단 평가서 요약 / 하단 내용·검토의견 그리드 / 우측 승인패널(단계 이력 + 승인/반려/취소). **외곽 3컬럼=요약, 팝업 승인패널=상세**.

---

## 5. 종합검토의견 — 승인과 분리

기존엔 종합의견이 승인 액션의 산출물(승인 버튼→의견 팝업→단계별로 SYNTH_CONSTR_OP/SYNTH_SAF_OP/APPRV_CMT에 갈려 저장, 승인취소 시 내용 삭제)이었습니다. SCNT에서는 **승인과 완전히 분리**해 작성자가 본문에서 미리 채우는 입력 항목으로 둡니다.

| | 기존 (060) | SCNT (060_003) |
|---|---|---|
| 쓰는 시점 | 승인하면서 (결재자) | **미리, 본문에서** (작성자) |
| 검증 시점 | 각 결재 단계 | **승인요청 직전 1회** |
| 검증 범위 | 자기 것 1개 | **공사팀·안전팀 종합의견 둘 다** |
| 승인취소 시 | 내용 초기화 | **보존** |

옵션092(종합검토의견 사용)=T면 SYNTH_CONSTR_OP·SYNTH_SAF_OP 중 하나라도 비면 승인요청 차단. FE 1차 + BE `validateBeforeDemand` 재검증(2겹).

## 6. 현재 진행 상황 (2026-07-20 기준)

- ✅ 승인 팝업 신규 화면 / DDL 4컬럼 / 옵션 배선(`bUseOpt060003`) / 외곽 승인 컬럼(상태+단계+대기자+벌크 병합) / 소급 유지
- 🔜 남은 작업: 상태부여 seam · 수정/삭제/잠금 seam(EDIT_TF, 정합·보안 직결) · 종합의견 승인요청 게이트 · 옵션 admin + SQL 일괄수정(최대 리스크) · USETGT 등록/승인라인 정의

> 이후 갱신: SanctionTargetHandler(OTAT) 요청/승인/반려/취소 시 CFM_* write는 구현 완료.

---

## 7. 아직 확정 안 된 것

- **승인 단계 ↔ 종합의견 컬럼 매핑**: SCNT는 라인이 커스텀이라 단계별 고정 매핑이 성립 안 함 → 현재는 역기록 없이 별도 항목 유지, 필요 시 승인자 직책 기준 매핑 검토.
- **레거시 `STTS_CD` ↔ SCNT 상태 정합**: SQL 일괄수정 시 상태 버킷(20/60, 30~60)이 SCNT 현장에서도 성립하는지 확인 필요.
