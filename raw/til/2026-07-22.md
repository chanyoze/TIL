# 2026-07-22 Playwright E2E 테스트 확장하며 배운 것

프론트엔드 E2E 테스트를 16개 → 46개로 확장. 백엔드 없이 프론트 단독으로 동작을 검증하는 방법 위주. (실무 프로젝트에서 배운 것을 일반화)

## 1. API 모킹으로 백엔드 없이 FE 단독 E2E
- `page.route()`로 REST 응답을 가짜로 가로챔
- 서버 상태를 테스트 내 배열로 들고 생성/수정/삭제를 반영 → "생성했더니 목록에 뜬다"까지 검증
- 나중에 실제 백엔드 연동으로 승격 가능 (같은 시나리오, 진짜 DB)

## 2. 인증 우회
- sessionStorage 기반 로그인 게이트를 `addInitScript`로 미리 주입해 보호 페이지 접근

## 3. 모킹 응답을 인터셉터 언랩 형태에 맞춰야
- 앱의 http 인터셉터가 응답 래퍼를 벗김 (목록이면 `{items, total}`, 단건이면 `data`)
- 모킹 응답도 그 래퍼 형태(`dataType`, `data`, `totalDataCnt`)로 만들어야 앱이 제대로 받음
- 교훈: 모킹은 "네트워크 응답 원형"을 흉내내야지, 앱이 최종적으로 쓰는 형태가 아님

## 4. 디버깅 — 컴포넌트가 요구하는 필드를 seed에 맞춰야
- 목록이 안 떠서 추적 → 카드 컴포넌트가 `post.views.toLocaleString()` 호출
- seed 데이터에 `views`가 없어 `undefined.toLocaleString()` 크래시 → 렌더 전체가 죽음
- 교훈: 모킹 seed 필드를 **실제 렌더 컴포넌트가 읽는 필드**에 맞춰야. 하나만 빠져도 침묵 크래시

## 5. 병렬 부하
- 46개를 16워커로 돌리면 단일 dev 서버(vite 하나)가 과부하 → a11y/visual이 타이밍으로 실패
- `--workers=4`로 낮추니 안정. 테스트 수보다 서버 처리량이 병목

## 6. 시각 회귀 baseline은 코드 변경을 따라가야
- 화면을 고치면(예: 공통 레이아웃에 요소 추가) 스냅샷 baseline이 낡아 실패
- `--update-snapshots`로 갱신. "실패"가 항상 회귀는 아님 — 정당한 변경일 수 있음

## 7. axe wcag2aa는 AA 레벨 전용 태그
- `withTags(['wcag2aa'])`면 검사 규칙이 **2종**(color-contrast, meta-viewport)만
- `image-alt`·`label`·`link-name` 등 흔한 규칙은 사실 **wcag2a(A 레벨)** 라 AA 필터에 안 걸림
- 전체 접근성 보려면 `withTags(['wcag2a','wcag2aa','best-practice'])` → 43종·수백 노드 검사
- 게이트를 "색 대비 하나만 강제"로 좁히려면 wcag2aa만, 넓게 보려면 태그 확장

## 8. Playwright UI 모드(--ui) > HTML 리포트
- UI 모드는 **액션 리스트 + 그 순간 실제 화면 스냅샷 + 테스트 트리**를 동시에 보여줌
- 타임라인을 스크럽하면 화면이 단계별로 바뀜
- 정적 HTML 리포트보다 "테스트가 이렇게 돈다"는 변별력이 훨씬 높음 (시연·캡처에 유리)

## 9. 셀렉터 안정성은 UI 프레임워크에 달림
- 표준 DOM + 시맨틱 셀렉터(`getByRole`, `aria-label`)를 쓰는 프레임워크(Vue 등) → E2E 안정
- 자체 위젯 · 런타임 자동생성 id · iframe 중첩을 쓰는 레거시 엔터프라이즈 UI 프레임워크 → 셀렉터가 흔들려 안정적 E2E 어려움(접근은 되나 유지보수 부담, 사실상 미검증)
- 교훈: E2E 자동화 도입 가능성은 "화면을 얼마나 표준적으로 지목할 수 있나"가 좌우

## 10. CI에서 자동 실행
- 테스트·게이트를 로컬에서만 돌리면 반쪽 → CI(예: GitHub Actions)에서 PR마다 자동 실행
- 흐름: 코드 규칙 게이트 → 빌드 → E2E/접근성 → 하나라도 실패 = 머지 차단(required check)
- "내 PC에서만 통과"가 아니라 "팀 누구 코드든 같은 게이트 통과"가 핵심

## 곁가지 — 발표자료/문서 관리
- 슬라이드를 MD(정본) + HTML(실물) 이중 관리 시, 한쪽 고치면 다른 쪽도 동기화해야 어긋나지 않음
- 슬라이드 번호 재정렬은 정규식 스크립트로 일괄(수동 번호는 실수 남)
