빌드·배포 파이프라인(젠킨스 등)이 "성공"으로 끝났는데 막상 접속하면 **흰 화면(blank page)** 만 뜰 때가 있다. 코드 문제가 아니라 **서버 프로세스(컨테이너)가 정상적으로 다시 올라오지 못한** 경우가 많다. 이때 사내 운영 MCP 도구로 해당 서버를 재시작하면 빠르게 복구된다.

## 증상

- 배포 잡(job)은 초록불(성공)인데, 사이트는 흰 화면 또는 502/응답 없음.
- 새로고침해도 동일. 직전 코드 변경과 무관하게 화면이 안 뜸.

## 원인

- 배포 과정에서 서버 프로세스/컨테이너가 내려간 뒤 **다시 기동되지 않은** 상태.
- 빌드 산출물은 갱신됐지만 이를 서빙하는 런타임이 떠 있지 않아 빈 응답이 나간다.

## 조치 — 운영 MCP 로 재시작

서버에 직접 들어가 셸 명령을 치지 않고, **MCP 도구가 제공하는 서비스 목록**을 통해 재시작한다.

1. **대상 찾기** — "개발 API 서버" 같은 말을 정확한 서비스로 바꾼다. 같은 이름이 개발 · 운영 양쪽에 있으면 환경을 먼저 구분한다.
2. **재시작** — 운영 환경은 한 번 더 확인을 거친다.
3. **상태 확인** — 잠시 뒤 컨테이너가 다시 올라와 정상 상태가 됐는지 본다.

## 핵심

- "배포는 성공인데 흰 화면" → 코드보다 **런타임이 안 떠 있는지**를 먼저 의심한다.
- 재시작은 **서비스 목록 기반 도구**로 하면 셸 접근 없이 처리할 수 있고, 운영은 한 번 더 확인해 실수를 줄인다.
- MCP(Model Context Protocol): 외부 도구/데이터를 표준화된 방식으로 AI에 연결하는 프로토콜. 여기선 인프라 재시작 명령을 도구로 노출한 것.
