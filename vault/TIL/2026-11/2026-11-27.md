**오늘의 한 줄** — 공개 여부는 화면이 아니라 저장소와 이력이 정하고, 파일을 쓰는 도구는 모르는 입력 앞에서 멈춰야 한다.

## 1. 공개 저장소의 잠금은 가림일 뿐이다

- **한 일**: 이 사이트의 비밀번호 잠금과 오래된 위젯을 걷어내고, 공개하지 않을 글은 비공개 보관함으로 옮겼다.
- **얻어간 점**: 저장소가 공개면 화면 잠금은 방문자만 막고 소스는 누구나 본다. 내린 글도 git 이력에 그대로 남는다. 공개 판단은 글 단위로 하고, 안 보일 글은 처음부터 비공개 쪽에 둔다.
- **다음에**: 공개 저장소에서 글을 내릴 때는 이력까지 함께 처리한다.

## 2. 줄바꿈 하나로 생긴 "낡음" 오탐

- **한 일**: 문서 점검 스크립트를 정비했다.
- **얻어간 점**: 작업 트리는 CRLF, 스크립트가 만든 결과는 LF 라서 내용이 같아도 검사가 "낡음" 이라고 했다. 또 인덱스 생성 스크립트가 모르는 플래그(`--help`)를 무시하고 실제 파일을 다시 썼다.
- **다음에**: 파일 비교는 줄바꿈을 맞춘 뒤 한다. 파일을 쓰는 스크립트는 아는 플래그만 받고, 모르면 멈춘다.

## 3. 자기 검증은 임시 폴더에서

- **한 일**: 점검 스크립트의 자기 검증을 임시 폴더 픽스처로 넓히고, 옛 판 스크립트가 깔려 있으면 실제 폴더에 쓰기 전에 멈추는 가드를 넣었다.
- **얻어간 점**: 검증 코드가 실제 폴더를 건드리면 검증이 곧 사고가 된다. 설치본이 정본보다 옛 판일 때가 가장 위험하다.
- **다음에**: 쓰기가 있는 도구의 테스트는 임시 폴더와 "옛 판이면 멈춤" 가드부터 만든다.

## 4. 고침은 스위치로, 기본은 끔

- **한 일**: 답변 조립을 바꾸는 고침 네 가지를 각각 스위치로 넣고 모두 기본 끔으로 두었다. 끈 상태에서 이전과 결과가 같음을 확인했다. 반영이 끝난 일회성 패치 스크립트는 지웠다.
- **얻어간 점**: 여러 고침을 한꺼번에 켜면 무엇이 효과였는지 알 수 없다. "끄면 이전과 같다" 를 먼저 증명하면 하나씩 켜며 잴 수 있다.
- **다음에**: 동작을 바꾸는 고침은 스위치와 끔 상태 회귀 0 부터 보인다.

## 5. 사람 검토와 자동화의 길을 나눈다

- **한 일**: 개인 저장소의 흐름을 정했다. AI 는 작업 브랜치에서 PR 까지 만들고, 머지는 사람이 한다. 매번 같은 기계 작업(자동 게시 · 밤 정리)은 main 에 바로 커밋한다.
- **얻어간 점**: 사람이 봐야 하는 변경과 반복되는 기계 작업을 한 길에 두면 둘 다 막힌다.
- **다음에**: 자동화를 새로 만들 때 PR 길인지 직접 커밋 길인지부터 정한다.

## 복습 질문

<details>
<summary>1. 공개 저장소에서 글을 지웠는데 왜 아직 안전하지 않을 수 있나?</summary>

git 이력에 남아 옛 커밋에서 누구나 볼 수 있다. 이력까지 따로 처리해야 한다.

</details>

<details>
<summary>2. 내용이 같은데 검사가 "낡음" 이라고 할 때 먼저 볼 것은?</summary>

줄바꿈(CRLF · LF) 차이다. 비교 전에 정규화한다.

</details>

<details>
<summary>3. 고침 여러 개를 안전하게 넣는 순서는?</summary>

스위치로 넣고 기본 끔 → 끈 상태 회귀 0 확인 → 하나씩 켜며 잰다.

</details>
