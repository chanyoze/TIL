# 발표자료 검수 기록 — 2026-08-19

발표 하루 전, 덱(`최종-발표자료.html`)과 대본(`최종-발표대본.md`) **두 문서를 서로 대조**해 불일치를 잡고 논지를 보강한 기록이다.
핵심은 "덱에 있는데 대본이 안 읽는 것"과 "대본에 있는데 덱과 숫자가 다른 것" 두 가지였다.

원문은 [9. 발표 대본 원문](./9-발표대본-원문)에 있다.

## 무엇이 문제였나

두 문서를 따로 고쳐 오다 보니 **같은 사실이 서로 다른 숫자로 적혀 있었다.** 발표에서 화면과 말이 어긋나면 그 자리에서 신뢰가 깎인다.

| 항목 | 덱 | 대본 부록 | 실측 |
|---|---|---|---|
| 실험 소요 시간 | 2.7배 | "두 배 반" | 13분→35분 = 2.69배 |
| 토큰 비용 | 1.7배 | "한 배 반" | 18만→30만 = 1.67배 |
| 개당 단가 | "거의 같다" | "같았다" | 1,667 vs 1,734 |

경영진 질문이 가장 먼저 꽂히는 자리(부록 B-1)에서 **덱이 대본을 반박하는 상태**였다. 덱 쪽이 실측과 맞아 대본을 덱에 맞췄다.

## 용어 — "기계"와 "AI"를 분리

E2E 테스트를 대본이 "**AI가** 실행한다"고 말하고 있었다. 사실이 아니다.

- **AI가 한 것** — 테스트 코드 작성, 실패 로그 판독
- **툴(Playwright)이 한 것** — 실행. 정해진 순서대로 도는 결정론적 스크립트다

이걸 뭉뚱그리면 앞서 "색 검사는 일부러 AI가 아닌 정규식으로 만들었다"고 강조한 대목과 앞뒤가 안 맞고, 「그럼 테스트도 매번 결과가 달라지나?」라는 질문을 자초한다.

→ 14~16장은 **툴/Playwright가 실행**, 17장은 **AI가 작성·판독**으로 분리. 14장 제목도 `사람 눈에서 기계로` → `사람 눈에서 자동 검증으로`.

## 시나리오를 먼저 정의한다 — 15장 보강

가장 크게 보강한 부분. 기존 대본은 "툴이 클릭을 재생한다"까지만 말하고, 정작 **"사람이 시나리오를 먼저 정의한다"**는 순서를 빠뜨리고 있었다.

이 프로젝트의 E2E 테스트는 이름이 한국어 문장으로 적혀 있다.

```
FAQ 생성 → 목록에 나타난다
질문을 비우고 저장하면 유효성 에러가 뜬다
9개 초과면 첫 페이지엔 10번째 글이 안 보인다
다크 토글이 html.dark 를 켜고 새로고침해도 유지된다
```

즉 **테스트 목록이 곧 명세서**다. 문서를 따로 만들면 코드와 갈라지지만, 이건 문서가 곧 실행되니 갈라질 수가 없다.

그리고 이 목록은 마침 15장 스크린샷 **왼쪽 패널에 이미 떠 있었다.** 새 이미지 없이 대본만 고쳐서 보강할 수 있었던 이유다.

한 발 더 나가면 **시나리오는 스택 독립적**이다. "FAQ를 만들면 목록에 나타난다"는 Vue든 뭐든 성립한다. 스택을 옮길 때 다시 쓰는 건 실행 부분이고, 무엇을 확인할지는 그대로 간다 — 이걸 17장에 추가해 "테스트를 차세대에 그대로 옮긴다"는 주장의 근거를 **셀렉터 규약 + 시나리오 두 겹**으로 만들었다.

## 스킬 슬라이드가 자기 근거를 안 읽고 있었다

`html-to-vue` 스킬 장(9장)이 약해 보인다는 지적을 받고 확인해 보니, **덱에는 A/B 실험이 이미 있는데 대본이 숫자를 하나도 안 읽고 있었다.**

> A: 스킬 없이 그냥 "Vue로 바꿔줘" · B: 스킬 걸고 같은 지시 — 같은 화면·모델로 **각 3회**

| 스킬에 박아둔 것 | 스킬 없을 때 |
|---|---|
| 인벤토리 대조 | 서명 이미지 유실 — **A 0/3 · B 3/3** |
| 자산 위치 안내 | "폴더에 없음"이라며 버림 |
| 함정 — Tailwind 오타색 | **빌드 통과·화면엔 색 안 나옴** |
| 요소 보존 (3회) | **A 3/4 vs B 4/4** · 토큰 +12.5% · 시간 +56% |

대본은 이걸 "이런 일이 있었습니다"라는 **일화로 격하**시켜 놓았다. 「3번 시켰더니 3번 다 놓쳤고, 스킬 걸었더니 3번 다 잡았습니다」와는 무게가 다르다.

특히 「**빌드는 통과하는데 화면엔 색이 안 나온다**」는 뒤에 나오는 「실행만 하면 초록이 되는 무늬만 테스트」와 **정확히 같은 논리**인데 입으로 말하지 않고 있었다. 초록불이 곧 정상이 아니라는 것 — 이 발표를 관통하는 문장이다.

→ 9장을 덱 수치로 재작성. 규모 자랑("265줄짜리 규칙")은 뺐다. 청중에게 줄 수는 의미가 없고 「그 문서 유지보수는 누가 하냐」를 부를 뿐이다.

## 접근성은 기능이 아니다

목록이 이렇게 되어 있었다.

> 레거시엔 없던 것들을 새로 얹었습니다 — 반응형, 다크 모드, 관리자 편집기, **그리고 접근성입니다.**

앞 셋은 "없던 물건을 새로 붙인 것"인데 **접근성만 성격이 다르다.** 접근성은 기능(feature)이 아니라 품질 속성(quality attribute)이라 나열하면 어색하다.

"접근성을 개선했다"도 정확하지 않았다. aria 속성이 0개였으니 개선이 아니라 신규 도입에 가깝다. 가장 정확한 건 **"기준을 맞췄다"** — WCAG AA라는 외부 기준이 실제로 있고 자동 검사로 상시 확인하니까.

→ 목록에서 빼고 독립 문장으로. `접근성은 WCAG AA 기준에 맞췄습니다 — aria 0 → 13, alt 전량, 색 대비도 기준 미달이던 걸 잡아 고쳤습니다.`

## 모킹 질문에 답이 없었다

덱 14장은 CUD 테스트 7개를 `(모킹)`이라고 **정직하게 표기**해 두었다. 숨긴 건 없다. 문제는 예상질문 목록에 「모킹이면 실제 저장은 검증 안 된 거죠?」에 대한 답이 **없었다**는 것이다.

하필 그 직전 슬라이드가 「'뜨는 것'과 '동작하는 것'은 다릅니다」로 가장 세게 미는 장이라, 질문이 붙기 딱 좋은 자리였다.

답할 재료는 이미 다 있었다 — **화면 동작은 프론트 7개, 실제 저장은 백엔드 통합 테스트 48개, 둘이 붙는 건 시연으로 확인.** 예상질문에 추가하고 약점 목록에도 항목을 넣었다.

## 부록을 실수로 넘기지 않게

마지막 내용 슬라이드 바로 뒤가 부록이라, 마무리 인사 후 엔터를 한 번 더 누르면 부록이 튀어나오는 구조였다.

→ 사이에 **「감사합니다」 장을 신설.** 이제 발표는 거기서 끝나고, 부록은 질문이 나올 때만 한 번 더 넘긴다. 질문받는 동안 「감사합니다」 화면을 띄워둘 수 있다.

## Playwright로 덱 자체를 회귀 검사

HTML을 여섯 곳 고쳤는데 브라우저로 열어본 적이 없었다. 슬라이드 덱은 `overflow-y: auto`라 **넘쳐도 잘리지 않고 조용히 스크롤된다** — 발표 중에 발견하면 늦는다.

프로젝트에 이미 깔려 있는 Playwright로 전 슬라이드를 순회하며 `scrollHeight - clientHeight`를 쟀다.

```js
const m = await page.evaluate(() => {
  const s = document.querySelector('.slide.active');
  return { scroll: s.scrollHeight, client: s.clientHeight };
});
```

해상도 4종(1920×1080 / 1600×900 / 1366×768 / 1280×720)에서 전 슬라이드를 돌린 결과 **콘텐츠가 화면 밖으로 나가는 장은 0건**이었다. 일부 장에서 잡힌 수십 px 차이는 콘텐츠가 아니라 하단 패딩이 압축된 것으로, 마지막 요소의 `bottom`이 뷰포트 안에 있는 것까지 확인했다.

**배운 것** — 발표 덱이 HTML이면 렌더 검사를 자동화할 수 있다. 눈으로 28장을 4개 해상도로 훑는 것보다 정확하고 빠르다.

## 정리 — 이런 검수는 무엇을 보는가

1. **두 문서가 같은 사실을 다르게 말하지 않는가** — 숫자는 한쪽을 정본으로 정하고 맞춘다
2. **화면에 있는데 입으로 안 읽는 근거가 없는가** — 가장 흔한 손실이다
3. **행위 주체를 정확히 부르는가** — "AI가"와 "툴이"를 뭉개면 다른 주장까지 흔들린다
4. **가장 세게 미는 장 직후에 나올 질문에 답이 있는가**
5. **레이아웃은 실제로 렌더해서 확인했는가**
