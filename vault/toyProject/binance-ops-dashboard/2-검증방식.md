# 검증 방식 — 이 프로젝트에서 제일 건질 것

> **"통과는 아무것도 말해주지 않는다."**

테스트를 몇 개 썼는지가 아니라, **무엇을 테스트하기로 했고 그 테스트가 실제로 무언가를
지키는지 어떻게 확인했는지**의 기록. 원문은
[docs/TESTING.md](https://github.com/chanyoze/binance-ops-dashboard/blob/main/docs/TESTING.md).

```bash
npm run typecheck      # 경계 안쪽
npm test               # 228건 (단위 195 + 통합 33)
npm run test:mutate    # 그 테스트가 실제로 무엇을 지키는지
npm run demo:chaos     # 진짜 네트워크·프로세스를 태우는 경로
```

---

## 1. 출발점 — 아무것도 검증하지 않는 테스트가 두 번 나왔다

둘 다 초록불이었고, 둘 다 지키는 것이 없었다.

**하나.** "구독자 하나가 터져도 나머지 전송은 계속된다"는 테스트가, 로컬 배열에 함수 두 개를
만들어 **테스트가 스스로 try/catch 로 돌리고** 결과를 확인하고 있었다. 모듈의 `broadcast()`
는 한 번도 호출되지 않았다. 즉 **거기 있는 try/catch 를 통째로 지워도 이 테스트는 통과한다.**

**둘.** rate limit 테스트에서 "아직 대기 중인가"를 확인하는 헬퍼를
`Promise.race([p.then(...), Promise.resolve(marker)])` 로 짰다. 이미 끝난 약속이어도 마커 쪽이
한 틱 빠르다. 그 헬퍼는 **항상 "대기 중"이라고 답했고** 그것을 쓴 단언 세 개가 전부 무의미했다.

둘 다 코드 리뷰를 통과했고, 둘 다 **일부러 망가뜨려 보고 나서야** 드러났다.

---

## 2. 무엇을 테스트할지 고르는 기준

커버리지를 올리려고 고르지 않는다. 다음 두 부류만 고른다.

| 부류 | 뜻 | 예 |
|---|---|---|
| **데이터에 구멍이 나는 곳** | 여기가 틀리면 수집이 멈추거나 봉이 비는데 나중에야 안다 | 갭 계산, UPSERT 멱등성, weight 관리, 재연결·watchdog |
| **화면이 조용히 거짓말하는 곳** | 오류도 로그도 없이 틀린 값을 맞다고 보여준다 | 지표 정의, 봉 병합, 표시 시간대, Lag 임계 |

공통점은 **틀려도 시끄럽지 않다**는 것. 부팅이 실패하는 종류(설정 파싱 등)는 테스트하지
않는다 — 틀리면 그 자리에서 시끄럽게 죽으므로 이미 안전하다.

**타입이 닿지 않는 경계**를 특히 봤다. Binance 응답은 REST 가 배열 인덱스(`row[9]`, `row[10]`),
WS 가 한 글자 키(`k.v`, `k.q`, `k.V`, `k.Q`)다. **바꿔 써도 타입은 통과하고 파싱도 성공하고
저장도 된다.** 화면에는 그럴듯한 숫자가 뜬다.

## 3. 계층마다 사각이 있다

| 계층 | 보는 것 | **못 보는 것** |
|---|---|---|
| 타입체크 | 경계 안쪽의 형태 | 런타임 값. `sql<Date>` 는 단언일 뿐 변환이 아니다 |
| 단위 테스트 | 판단이 맞는가 | 진짜 네트워크·DB·브라우저 |
| 통합 테스트 | DB 와의 계약 | 축·레이아웃 같은 시각 결함 |
| 육안 검수 | 축·겹침·스케일 | 색 대비처럼 눈으로 못 재는 것 |
| 색 대비 검증기 | 색 | 다른 모든 것 |
| **환경** | 프록시·컨테이너 뒤에서의 동작 | — |

**마지막 줄을 가장 늦게 알았다.** SSE 라우트가 붙인 `Cache-Control: no-transform` 을
`next.config.ts` 의 일괄 규칙이 덮고 있었는데 로컬에서는 증상이 **전혀** 없다. 중간에 프록시가
없기 때문이다. 타입체크도, 테스트도, 두 차례의 코드 리뷰도 잡지 못했다 — 셋 다 **코드만** 본다.

### 검증 도구 자체에도 사각이 있다

좁은 화면 레이아웃을 고치며 `body` 의 `overflow: hidden` 을 함께 풀지 않았다.
`body` 의 overflow 는 **뷰포트로 전파되므로** 내용은 아래로 자라는데 화면은 내려가지 않았다.

| 확인에 쓴 도구 | 왜 놓쳤나 |
|---|---|
| 전체 페이지 스크린샷 | `captureBeyondViewport` 는 **`overflow: hidden` 이어도 전체 문서를 그린다** |
| 프로그래밍 스크롤(`window.scrollTo`) | 프로그래밍 스크롤은 **뷰포트 overflow 를 통과한다** |

둘 다 "잘 나온다"고 답했고 실제 기기에서 만져 본 사람이 잡았다. 지금은
`getComputedStyle(body).overflow` 와 문서·뷰포트 높이 차이를 직접 잰다 — 우회되지 않는 신호다.

> **검증 도구가 "우회 가능한 신호"를 보고 있지 않은지 확인해야 한다.**
> 도구가 초록불을 켰다는 사실 자체가, 그 도구가 무엇을 보는지 모르면 아무 의미가 없다.

## 4. 변이 검증 — 테스트를 테스트한다

스크립트가 코드를 **일부러 망가뜨리고**, 대상 테스트를 돌리고, **실패하는지** 확인한 뒤
원본을 되돌린다. 빠져나가는 변이가 하나라도 있으면 종료 코드 1.

```
  [1/17] rest-taker-swap            잡힘
  [2/17] ws-volume-swap             잡힘
  ...
  ✓ PASS — 변이 17건이 모두 잡혔습니다.
```

각 항목은 **"이 코드가 이렇게 틀리면 이런 일이 난다"** 를 실행 가능한 형태로 적은 것이다.

| 변이 | 망가지면 생기는 일 |
|---|---|
| WS 의 `v`/`q` 맞바꿈 | 글자 하나 차이. 사람이 가장 틀리기 쉽다 |
| 4xx 재시도 | 같은 요청을 반복해 rate limit 을 태우고 구멍이 넓어진다 |
| 무결성 스캐너의 심볼 격리 제거 | 앞 심볼의 실패가 뒤 심볼의 스캔을 데려간다 |
| 스트림 멎음 판정 무력화 | 화면이 "연결됨"이라고 말한 채 영원히 멈춘다 |
| 표시 시간대 되돌리기 | 시각이 아홉 시간 밀려도 화면은 멀쩡하다 |
| **UPSERT 를 DO NOTHING 으로** | 이 설계의 **전제**. 미완성 봉이 확정 봉으로 덮이지 않고 고착된다 |
| 갭 판정 무력화 | 구멍을 못 찾으면 **마지막 방어선이 사라진다** |

## 5. 이 절차가 실제로 잡은 것

주장이 아니라 기록이다. 전부 커밋에 남아 있다.

| 무엇 | 어떻게 드러났나 |
|---|---|
| 테스트가 자기 자신을 검증 | 코드 리뷰 |
| 대기 판정 헬퍼가 항상 "대기 중" | **변이 검증** (기본값 60초→1초로 바꿨는데 12건이 그대로 통과) |
| 라우트 테스트가 우연히 통과 | **변이 검증** (설정이 마침 `'1m'` 이라 하드코딩해도 통과) |
| `no-transform` 이 나가지 않음 | **환경** (프록시 뒤에 올려 보고) |
| `EventSource` 가 헤더만 받아도 `open` | **환경** |
| DB 가 죽자 수집기까지 죽음 | **장애 주입** (`demo:chaos --db` 를 만들다가) |
| 좁은 화면에서 스크롤이 막힘 | **실제 기기** — 스크린샷과 프로그래밍 스크롤은 둘 다 놓쳤다 |
| 초록/빨강의 색약 대비 부족 | **색 대비 검증기** (정상 ΔE 33.9 / 색약 **4.1**) |

**같은 계층이 두 번 잡은 적은 거의 없다. 계층을 늘린 만큼 잡혔다.**

## 6. 카오스 데모 — 죽였다 살려서 증명한다

"재시작하면 갭을 백필한다"를 문장으로 두지 않고 **돌려볼 수 있게** 만들었다.

```bash
npm run demo:chaos              # 수집기를 3분간 중단했다 재개하고 복구를 검증
npm run demo:chaos -- --kill    # SIGKILL 로 죽여 자동 재시작 경로 확인
npm run demo:chaos -- --db      # 수집기 대신 DB 를 죽인다
```

중단 전후 적재 현황·백필이 메운 봉 수·남은 구멍 수를 표로 출력하고 PASS/FAIL 을 낸다.

`--db` 는 **쓰기 버퍼를 두지 않기로 한 결정을 검증한다.** 세 가지를 본다 — 수집기가
**재시작조차 하지 않는가**, 실제로 구멍이 생기는가, 그 구멍이 **재시작 없이** 메워지는가.

> 이 시나리오를 만들다 실제 버그를 찾았다. `pg` 커넥션 풀은 유휴 커넥션이 죽으면 `error` 를
> emit 하는데 듣는 곳이 없었고, Postgres 종료 메시지가 **처리되지 않은 예외로 올라와
> 수집기를 죽였다.** 문서가 "DB 장애 시 스캐너가 회수한다"고 말하는 동안, 정작 **회수할
> 프로세스가 함께 죽고 있었다.**

---

## 7. CI 가 세 단계를 전부 돌린다

타입체크 → 테스트(**DB 없이 한 번 · 통합까지 한 번**) → 변이 검증.

통합 테스트가 DB 없이 조용히 넘어가는 것은 의도한 설계다. 이 저장소를 처음 받은 사람이
Postgres 를 띄우지 않고 `npm test` 를 돌려도 막히지 않아야 하고, CI 는 **그 약속이 지켜지는지도**
함께 확인한다.

---

## 남는 교훈

1. **통과는 아무것도 말해주지 않는다.** 초록불은 "테스트가 돌았다"는 뜻이지 "지켰다"가 아니다.
2. **테스트를 붙이는 것으로 끝내지 않는다.** 일부러 망가뜨려 봐야 지키는지 안다.
3. **계층마다 사각이 있고, 마지막 사각은 환경이다.** 코드만 보는 검증은 코드 밖을 못 본다.
4. **검증 도구가 우회 가능한 신호를 보고 있지 않은지 확인한다.**
