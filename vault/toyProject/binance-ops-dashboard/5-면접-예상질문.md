# 예상 질문 → 한 문장 답

> **면접에서는 한 문장 답을 먼저 말하고, 상대가 더 물으면 근거를 편다.**
> 처음부터 길게 풀면 상대가 무엇을 궁금해하는지 모른 채 혼자 말하게 된다.

---

## 1. 한 문장 답 (40개)

| 질문 | 답 |
|---|---|
| 이 프로젝트 한 줄로? | 구멍이 생기면 스스로 메우는 수집 파이프라인과, 그 파이프라인의 건강을 보여주는 대시보드 |
| 왜 프로세스를 분리했나 | 생명주기가 다르다. 합치면 **CSS 한 줄 수정이 데이터에 구멍을 낸다** |
| 백필을 왜 하나로 합쳤나 | 같은 질문("마지막 봉이 언제인가")이기 때문. 분리하면 **분기 버그가 재시작 때만 터진다** |
| 멱등성이 왜 전제인가 | 구간을 겹치게 긁을 수 있어야 복구가 단순해진다. 없으면 통합 설계 전체가 무너진다 |
| 재시작 시 마지막 봉부터 다시 긁는 이유 | 그 봉이 **미완성으로 저장돼 있을 수 있다** |
| WS 가 끊긴 걸 어떻게 아나 | close 이벤트 + **watchdog**. 소켓이 OPEN 인데 조용한 좀비를 10초 임계로 잡는다 |
| 좀비를 왜 `close()` 가 아니라 `terminate()` 로? | 응답 없는 소켓은 **close 핸드셰이크도 못 끝낸다.** 거기서 다시 멈춘다 |
| DB 가 죽으면? | 구멍으로 남기고 스캐너가 회수. 버퍼를 안 두는 이유는 **원본이 Binance 에 있어서** |
| Kafka 같은 큐를 앞단에 두지 않은 이유 | 같은 답이다. 복구 가능한 원본이 외부에 있는데 자체 버퍼를 만드는 건 해결된 문제를 다시 만드는 일 |
| 확장하려면? | **심볼 단위 샤딩.** 심볼이 `SYMBOLS` 환경변수로만 들어오는 게 그 준비다 |
| 서버리스로 옮기면? | `LISTEN/NOTIFY` 가 안 된다. 그래서 `RealtimeBus` 뒤에 뒀고 **Redis 구현으로 갈면 나머지는 그대로** |
| 왜 InfluxDB 같은 시계열 DB 가 아닌가 | 데이터 **모양**이 시계열인 것과 시계열 DB 의 **이점이 필요한 것**은 다릅니다. 이 시스템이 요구한 건 처리량이 아니라 같은 구간을 몇 번 다시 써도 안전한 것이고, 그건 관계형 문법입니다. 2만 행에서 압축·다운샘플링은 발동하지 않고, 확장 경로는 TimescaleDB — **갈아타는 게 아니라 확장**입니다 |
| 왜 SSE 인가 | 통신이 **서버→클라 단방향**이다. 재연결이 브라우저에 내장돼 있고 평범한 HTTP 라 프록시를 그냥 통과한다 |
| SSE 를 골랐는데 폴백을 붙였으면 잘못 고른 것 아닌가 | 아닙니다. 수집기가 좀비 연결을 watchdog 으로 잡는 것과 **같은 원칙을 클라이언트에 적용**한 겁니다. 프로토콜 선택의 문제가 아니라, **어느 프로토콜이든 "열려 있는데 안 오는" 상태는 감지해야** 합니다 |
| 데모 화면의 "스트림 지연"은 뭔가 | 터널 앞단 프록시가 SSE 를 버퍼링합니다. 그 상태를 감지해 폴링으로 갱신 중이라는 표시입니다. **감추지 않고 README 에 설명해 뒀습니다** |
| 왜 1분봉만 수집하나 | 인터벌마다 수집하면 무결성 검증을 인터벌 수만큼 해야 하고 정합성 불일치가 생긴다. **검증할 진실을 하나로** |
| 왜 지표를 SQL 에서 계산하나 | 앱 메모리에 두면 재시작 시 리셋되고 인스턴스를 늘리면 값이 갈린다. 정의가 한 곳에 있어야 **화면이 조용히 거짓말하지 않는다** |
| 왜 aggTrade 를 저장 안 했나 | kline 이 `takerBuyBaseVolume` 로 이미 준다. 그리고 `fromId` 페이지네이션이라 **시간 기반 복구 모델과 축이 다르다** |
| 왜 이중 축을 안 썼나 | 눈금 설정만으로 착시를 만들 수 있다. **지수화로 단일 축** |
| Taker 축이 왜 ±15%p 인가 | ±100%p 로 잡으면 실제 값이 **중앙 1px 에 뭉갠다** |
| 초록/빨강을 왜 단독으로 안 쓰나 | 적록색약에서 두 색의 거리가 **ΔE 4.1**(최저선 6). 눈으로는 못 보는 결함이라 계산으로 잡았다 |
| 가장 위험했던 버그는 | `ws_connected_since` 유실. 타입체크도 검증기도 통과했고 **uptime 지표가 원천부터 죽어 있었다** |
| 타입스크립트를 쓰는데 왜 그런 게 나오나 | 타입은 **경계 안쪽**을 지킨다. DB·네트워크처럼 외부에서 값이 들어오는 지점에서 타입은 "주장"이 된다. 그래서 **경계에는 타입이 아니라 테스트를 둔다** |
| 테스트는 어떤 기준으로 골랐나 | 커버리지가 아니라 **"여기가 깨지면 데이터에 구멍이 난다"** 는 지점만 |
| 변이 검증이 뭔가 | 코드를 **일부러 망가뜨리고** 대상 테스트가 실패하는지 확인한 뒤 되돌린다. 빠져나가는 변이가 하나라도 있으면 실패 |
| 왜 그런 걸 만들었나 | 아무것도 검증하지 않는 테스트가 **실제로 두 번** 나왔고 둘 다 초록불이었다. **통과는 아무것도 말해주지 않는다** |
| AI 를 어떻게 썼나 | **판단은 내가, 검증은 자동화, 검수는 다시 내가.** 커밋 트레일러 대신 `AI-USAGE.md` 로 밝혔다 |
| AI 가 짜준 코드라 버그가 난 것 아닌가 | 사람이 짜도 나오는 종류다. 중요한 건 **그걸 잡는 장치를 미리 만들어 뒀는가** |
| 저장은 UTC 인데 화면은 왜 KST 인가 | **표시와 저장을 나눴다.** 시계열 정합성은 UTC 에 걸려 있어 저장·로그는 그대로 두고 화면만 바꿨다. 운영 화면의 첫 질문("얼마나 최신인가")의 기준은 보는 사람의 벽시계다. 대신 **절반만 바꾸지 않았다** — `demo:chaos` 출력도 맞췄고 캔들 툴팁에 KST·UTC 를 함께 적는다 |
| 왜 브라우저 로컬 시간이 아닌가 | 서버 렌더와 클라 렌더가 다른 시간대로 문자열을 만들면 **하이드레이션이 어긋나고**, 화면 시간대가 사람마다 다르면 캡처·문서와 화면이 안 맞는다. 고정하고 라벨로 밝힌다 |
| 가격을 왜 문자열로 다루나 | JS number 는 배정밀도라 시세를 정확히 표현 못 한다. Postgres `NUMERIC` ↔ TS `string`, **계산은 SQL 에서** |
| 마이그레이션을 왜 별도 서비스로 뺐나 | 수집기 부팅의 부수효과로 두면, 수집기가 못 뜨는 상황에서 **스키마가 영영 안 생기고 대시보드도 같이 죽는다** |
| rate limit 은 어떻게 다루나 | weight 카운터로 **능동 관리**. 분당 6000 중 80% 에서 스스로 늦추고 `Retry-After` 를 존중한다. 429 맞고 대응하면 이미 늦다 |
| 왜 배포를 안 했나 | 거래소가 **데이터센터 IP 를 차단**할 수 있고, 유휴 슬립 호스팅은 상시 수집 전제와 모순이다. 재현 경로가 주(主), 라이브 URL 이 부(副) |
| 왜 차트를 직접 구현했나 | 필요한 게 캔들·라인·다이버징 바 셋뿐이라 라이브러리를 들이는 것보다 **마크 규격을 쥐는 편이 낫다** |
| 아쉬운 점 / 한계는 | 단일 인스턴스 전제·서버리스 불가·인증 없음·실 API 미테스트. **넷 다 넘는 방법을 README 에 함께 적었다** |
| 더 시간이 있었다면 | 심볼 샤딩 실제 구현과 Redis 버스 구현체. **자리는 이미 만들어 뒀다** |

## 2. 실제로 터진 버그 — 각각이 하나의 교훈이다

**면접에서 가장 강한 재료다. 전부 타입체크를 통과한 상태였다.**

| 버그 | 무슨 일 | **교훈 (이 문장을 외운다)** |
|---|---|---|
| `sql<Date>` | 타입 단언일 뿐 런타임 변환이 아니라 timestamptz 에 문자열이 왔다. 하필 **백필 시작점을 정하는 함수**였고 재시작 때만 터졌다 | **타입은 경계 안쪽을 지키고, 경계에는 테스트를 둬야 한다** |
| `ws_connected_since` 가 항상 NULL | upsert 가 `excluded` 로 무조건 덮는데 1초 주기 티커 갱신이 그 필드를 안 넘겨 연결 1초 뒤 지워졌다. **uptime 지표가 원천부터 죽어 있었다** | **"없음"에 두 가지 뜻(미제공/삭제)이 섞이면 반드시 터진다** |
| 체결이 뜸한 심볼이 stale 로 보임 | 실행해야만 보이는 종류 | 화면에 올릴 값은 **DB 에서 실제로 꺼내 봐야** 안다 |
| 집계 anchor 가 심볼 필터 없이 전역 max | 실데이터에선 우연히 맞았고 통합 테스트에서 드러났다 | **우연히 맞는 것과 맞는 것은 다르다** |
| 무결성 스캔의 `try` 가 심볼 루프 **바깥** | 앞 심볼이 던지면 뒤 심볼 스캔이 그 주기째 사라진다 | **마지막 방어선은 격리되어 있어야 방어선이다** |
| SSE 구독 누수 3종 | `start()` 실패 시 유령 구독자 잔류 / `stopIfIdle` 이 `starting` 미확인 / `cleanup` 의 조기 반환이 해지를 삼킴 | 가드가 **정리를 막는** 경우가 있다 |
| 테스트가 자기 자신을 검증 | 로컬 배열을 만들어 테스트가 스스로 try/catch 로 돌렸다. **모듈의 try/catch 를 지워도 통과한다** | **통과하는 테스트와 회귀를 잡는 테스트는 다르다** |
| 가짜 소켓이 `close` 미발생 | 실제 `ws` 는 `terminate()` 뒤 반드시 `close` 를 낸다. watchdog 테스트가 "끊었다"까지만 보고 **다시 붙는지는 안 봤다** | **가짜가 실제와 다르면 테스트는 조용히 빈다** |
| `no-transform` 이 안 나감 | SSE 라우트가 붙인 헤더를 `next.config.ts` 일괄 규칙이 덮었다. **로컬에서는 증상이 0** — 프록시가 없으니까 | **검증 계층마다 사각이 있고, 마지막 사각은 "환경"이다** |
| 클라이언트에 watchdog 부재 | `EventSource` 는 헤더만 받아도 `open` 을 낸다. **서버는 같은 문제(좀비 연결)를 이미 풀어놨는데 브라우저엔 없었다** | **자기 원칙을 한쪽에만 적용하고 있지 않은지 본다** |
| 상대 강도 라벨 겹침 | 최소 간격 규칙을 넣었지만 여전히 붙었다 — **증상을 미룬 것이지 원인을 없앤 게 아니었다.** 값을 범례로 옮겨 문제 자체를 없앴다 | **"완화"와 "제거"를 구분한다** |
| DB 가 죽자 수집기까지 죽음 | `pg` 풀의 `error` 를 듣는 곳이 없어 Postgres 종료 메시지가 처리되지 않은 예외로 올라왔다. 문서가 "스캐너가 회수한다"고 말하는 동안 **회수할 프로세스가 함께 죽고 있었다** | 장애 시나리오는 **만들어 봐야** 안다 |

> **여기서 나온 절차 하나** — 고친 뒤 `git stash` 로 프로덕션 코드만 되돌려
> **새 테스트가 실제로 실패하는지 확인**했다. 두 건 모두 정확히 실패했다.
> **그제서야 그것을 회귀 테스트라고 부를 수 있다.** 이 말은 그대로 써도 좋다.

## 4. 마지막에 한 번 더

> **"통과는 아무것도 말해주지 않는다."**
>
> 아무것도 검증하지 않는 테스트가 실제로 두 번 나왔고 둘 다 초록불이었다.
> 그래서 테스트를 붙이는 것으로 끝내지 않고 **그 테스트를 한 번 더 검증한다.**

**"왜 처음부터 TDD 를 안 했나"** → 안 했고, 히스토리에 남아 있고, **그 실패에서 변이 검증이 나왔다.**
