# ✨ 코드 품질

- **DRY**: Don't Repeat Yourself. 같은 로직을 반복하지 말라는 원칙.
- **God Method**: 한 메서드가 너무 많은 책임을 지는 안티패턴. 관심사 분리로 해소.
- **매직 넘버**: 코드에 의미 없이 등장하는 숫자 리터럴. 상수로 추출해 이름을 붙이는 것이 관례.
- **관심사 분리**: Separation of Concerns. UI 구성·이벤트 처리·외부 호출·설정 로딩 등을 각자 다른 모듈로 나누는 설계 원칙.
- **Dead Code**: 호출되지 않거나 컴파일조차 안 되는, 실행에 무의미한 죽은 코드. 제거 대상.
- **리팩토링 (Refactoring)**: 외부 동작은 그대로 두고 내부 코드 구조·가독성을 개선하는 작업.
- **단어경계 치환 (Word-boundary replace)**: 식별자를 일괄 변경할 때 `ABC`가 `ABC_DEF`의 일부까지 바꾸지 않도록 앞뒤 경계를 확인하며 치환하는 방식. 부분문자열 오염은 막지만, "이미 바꾼 결과가 다시 매칭되는" 연쇄 치환은 막지 못한다.
- **연쇄 치환 (Cascading replace)**: 매핑을 순차 적용할 때 앞 규칙의 산출물이 뒤 규칙에 다시 걸려 이중 변환되는 현상(`A → A_STS → A_STS_STS`). 신규명이 구명을 접두로 포함할 때 발생하며, 토큰을 먼저 수집해 목표명을 1회만 계산하는 단일 패스로 해결한다.
- **기준선 (Baseline)**: 변경 전후를 비교할 때 "원래 상태"로 삼는 기준 시점. 다단계 작업에서 직전 단계를 기준선으로 쓰면 앞 단계가 만든 결함을 "원래 그랬던 것"으로 오분류하므로, 작업 착수 이전 시점을 써야 한다.
- **응답 키 (Response key)**: 서버가 조회 결과를 담을 때 쓰는 문자열 이름. 화면의 데이터셋 이름과 문자열로만 이어져 있어, 리네임 시 여기만 빠뜨리면 요청은 200으로 성공하고 에러도 없는데 화면의 그 목록만 비는 증상이 난다.
- **역참조 확인 (Reverse-reference check)**: 어떤 함수·쿼리를 바꾸기 전에 "나 말고 누가 이걸 부르는가"를 먼저 훑는 것. 화면마다 자기 사본을 갖는 구조에서는 이름이 같아도 독립이지만, 남이 내 서비스를 직접 호출하면 국소 리네임이 그 화면을 깨뜨린다.
- **고아 태그 (Orphan tag)**: 여러 줄에 걸친 마크업 요소를 줄 단위로 지울 때 여는 태그만 사라지고 남겨진 닫는 태그. 여는/닫는 개수 불일치로 드러나며, 요소 단위(여는 태그~짝 닫는 태그) 삭제로 예방한다.
- **멱등성 (Idempotency)**: 같은 연산을 몇 번 반복해도 결과가 한 번 실행한 것과 같은 성질. 재시도·중복 요청이 안전해지므로 복구 로직을 단순하게 만든다. (예: 같은 구간을 여러 번 다시 수집해도 데이터가 어긋나지 않는다)
