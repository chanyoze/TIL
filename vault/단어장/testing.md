# 🧪 테스트

- **JUnit**: 자바 표준 단위 테스트 프레임워크. `@Test` 메서드로 검증하고 `assertEquals` 등으로 결과를 단언한다(현재 JUnit 5).
- **단위 테스트 (Unit Test)**: 함수·클래스 같은 작은 단위의 동작을 독립적으로 자동 검증하는 테스트.
- **순수 함수 (Pure Function)**: 같은 입력에 항상 같은 출력을 내고 화면·파일·전역 상태 같은 부수효과가 없는 함수. 테스트하기 쉬워 CI 검증 대상으로 분리한다.
- **헤드리스 (Headless)**: 모니터·키보드·마우스가 없는 실행 환경(서버·CI 러너). GUI 작업을 시도하면 예외가 난다.
- **MockMvc**: 서버를 실제로 띄우지 않고 Spring MVC의 요청 처리 흐름(매핑·바인딩·변환·예외처리)만 통과시켜 검증하는 테스트 도구. HTTP 요청을 직접 조립하므로 **문서 도구나 브라우저가 개입하지 않는다** — "이 오류가 특정 클라이언트 전용인가"를 가려낼 때 유용하다.
- **변이 테스트 (Mutation Testing)**: 소스 코드를 일부러 조금씩 망가뜨린(변이) 뒤 테스트가 실패하는지 확인하는 검증 기법. 통과하는 테스트가 실제로 무언가를 지키는지 검사한다. 변이를 잡지 못하면(=테스트가 여전히 통과하면) 그 테스트는 무의미하다는 뜻.
- **커버리지 (Code Coverage)**: 테스트가 전체 코드 중 몇 퍼센트를 실제로 실행했는지 나타내는 지표. 라인·분기 등 기준이 여러 가지다. 다만 "실행했다"와 "검증했다"는 다르므로, 커버리지만 높고 단언이 부실한 무늬만 테스트는 걸러내지 못한다 — 그래서 변이 테스트와 함께 본다.
- **JaCoCo**: 자바 커버리지 측정 도구(Java Code Coverage). 빌드에 붙여 라인·분기 커버리지를 리포트로 뽑고, 최소 기준 미달 시 빌드를 실패시키는 게이트로도 쓴다.
- **PIT (pitest)**: 자바 변이 테스트 도구. 소스에 자동으로 변이를 심고 테스트가 그걸 잡아내는지(kill) 측정한다. 잡지 못한 변이(survived)가 곧 검증 구멍이다.
- **E2E 테스트 (End-to-End)**: 실제 사용자가 하듯 브라우저를 띄워 클릭·입력·이동을 재생하며 시스템 전체를 관통해 검증하는 테스트. 단위 테스트가 부품을, E2E가 조립된 제품을 본다.
- **Playwright**: 마이크로소프트가 만든 브라우저 자동화·E2E 테스트 도구. 실제 브라우저를 조종해 각 단계 화면과 트레이스를 남기므로 실패 지점을 화면째로 확인할 수 있다. `getByRole`·`getByLabel` 같은 **사람이 화면을 인식하는 기준**의 셀렉터를 권장하는데, 이렇게 짜면 디자인이 바뀌어도 테스트가 잘 깨지지 않는다.
- **시각 회귀 테스트 (Visual Regression)**: 화면을 이미지로 찍어 기준 이미지와 픽셀 단위로 비교해 의도치 않은 변화를 잡는 테스트. 마이그레이션처럼 "겉모습이 그대로여야 하는" 작업의 직접 증거가 된다. 단 OS·폰트 렌더 차이로 기준 이미지가 환경을 타므로, CI에 넣으려면 CI와 같은 환경에서 기준을 떠야 한다.
- **TestContainers**: 테스트 실행 시 실제 DB·브로커 등을 도커 컨테이너로 띄웠다가 끝나면 정리해 주는 라이브러리. 인메모리 DB로 대체할 때 생기는 "실제 환경에선 안 되는" 차이를 없앤다.
