## 1. 🔴 최우선 — 외부 계약 원복 지점

배치1·2에서 **다른 화면이 정한 키**를 잘못 바꿨다가 되돌린 자리입니다. 이번 작업에서 **가장 위험**합니다.

### 1-1. 일괄수정 팝업 (`SfasPopRegAssesmentApplyAll`)

평가서 목록에서 여러 건 선택 → 일괄수정 버튼 → 값 지정 후 적용

- [ ] **위험성등급** 일괄 적용 → 그리드에 반영되는가
- [ ] **중점등록** 일괄 적용 → 반영되는가
- [ ] **위험성등급(3단기법)** 일괄 적용 → 반영되는가
- [ ] **공사팀장** 일괄 적용 → 이름·사번 모두 반영되는가
- [ ] **현장소장(승인자)** 일괄 적용 → 반영되는가
- [ ] **회차** 일괄 적용 → 반영되는가

> 실패 시 증상: 팝업에서 값을 골라 적용했는데 **그리드가 그대로**거나 빈칸.
> 관련: `aoRtnDat.data.ASSMNT_RANK / PRIORITY / C_USER_NO / A_USER_NO / STAN_DEGREE`

### 1-2. 위험성등급 LOV (`SFAS_RISKGR`)

- [ ] 내용 그리드 **감소후등급** 칸 클릭 → LOV 팝업 → 등급 선택 → **값이 들어오는가**

> 관련: `sInColMap: "AFTER_ASSMNT_RANK_CD=ASSMNT_RANK"`

### 1-3. 리포트 출력 팝업 (`SfasPopRtrvAssesmentReciveRptAct`)

- [ ] 출력 버튼 → 팝업 진입 시 **회차·평가서가 선택된 상태로 뜨는가**
- [ ] 실제 출력물 생성까지 확인

> 관련: `"REGIS_SEQ=wdlAsmt.REG_SN"`, `"STAN_DEGREE=wdmScAll.COND_DEGREE"` (좌변 유지)

### 1-4. 재해사례 가져오기 팝업 (`SfasPopRegCompanyDisasterCase`)

- [ ] 재해사례 가져오기 → 팝업이 **해당 평가서 기준으로 뜨는가**
- [ ] 선택한 재해사례가 내용에 추가되는가

> 관련: `REG_SN: wdlAsmt.getCellData(..., "REG_SN")`

### 1-5. 평가서 내용 팝업 (`SfasPopRegAtRiskAsmt`)

- [ ] 해당 팝업 진입 → **데이터가 조회되는가** (빈 목록이면 실패)

> 관련: `REGIS_SEQ:` 좌변 유지 + 우변 `REG_SN`

## 2. 🔴 최우선 — 승인 모듈 (배치2 승인 핸들러 포함)

`oSanctnKeys` → 승인 코어 → OTAT 핸들러 → 핸들러 SQL 까지 `REGIS_SEQ` → `REG_SN` 으로 **체인 전체를 통일**했습니다. 한 곳이라도 어긋나면 승인 상태가 평가서에 역기록되지 않습니다.

### 2-1. 승인 팝업 조회

- [ ] 승인 대상 회차에서 승인 팝업 열기 → **평가서 헤더 정보가 뜨는가**
- [ ] **내용 그리드**가 채워지는가
- [ ] **공사팀장 검토의견 / 안전보건 검토의견** 목록이 뜨는가
- [ ] 재해사례 등록여부(`DR_CASE_REG_TF`) 표시 확인

### 2-2. 승인 액션 (핵심)

- [ ] **승인요청** → 성공 후 목록 상태가 `요청대기`/`승인대기` 로 바뀌는가
- [ ] **승인** → 상태 반영되는가
- [ ] **반려** → 상태 반영되는가
- [ ] **요청취소** → 상태가 되돌아가는가
- [ ] **승인취소** → 상태가 되돌아가는가

> ⚠️ 각 액션 후 **평가서 목록을 새로고침**해 `CFM_STS_CODE`/상태명이 실제로 갱신됐는지 확인.
> 상태가 안 바뀌면 핸들러의 `amData.get("REG_SN")` ↔ 화면 `oSanctnKeys` 불일치입니다.

### 2-3. 항목별 검토의견 검증 (배치1에서 고친 버그 자리)

옵션 `060_001` 을 `B`(전체항목) 또는 `C`(중점항목) 로 두고:

- [ ] **의견을 일부만 작성** → 승인요청 시 "등록되지 않은 검토의견이 있습니다" 로 **차단되는가**
- [ ] **의견을 전부 작성** → 승인요청이 **통과되는가**
- [ ] 옵션 `060_001 = A` → 검증 없이 통과되는가

> 관련: `selectCdRvwOpChkList` — 배치2에서 최상위를 `x.*` → 명시 컬럼으로 수동 보정한 쿼리.
> 출력 컬럼명이 `REG_DTL_SN` 인지가 관건이고, Oracle 파싱 검증은 통과했습니다.

## 4. 🟠 저장 — PK 바인드 전 구간

배치2가 `#{REGIS_SEQ}` → `#{REG_SN}` 으로 **바인드 254개소**를 바꿨습니다. 화면이 새 키를 보내지 않으면 **PK가 null 로 들어가** 저장이 실패하거나 엉뚱한 행을 건드립니다.

- [ ] 내용 **라인추가** → 저장 → 재조회 시 남아 있는가
- [ ] 내용 **수정** → 저장 → 반영되는가
- [ ] 내용 **삭제** → 저장 → 사라지는가
- [ ] **공사팀장 검토의견** 등록/수정/삭제 → 저장
- [ ] **안전보건 검토의견** 등록/수정/삭제 → 저장
- [ ] **종합검토의견**(옵션92) 저장
- [ ] 첨부파일·공정표 저장

> ⚠️ 저장 후 **반드시 재조회**해서 실제 반영을 확인하세요. 저장 성공 메시지만 보고 넘어가면 안 됩니다.

### 4-1. 재해형태 (집계 유지 + 유사어 코드 221줄 삭제)

- [ ] 재해형태 **LOV 선택** → 저장 → 에러 없이 완료
- [ ] 재해형태 **선택 취소** 후 저장 → 에러 없이 완료
- [ ] **AI로 라인추가** → 저장 → 에러 없이 완료
- [ ] 저장 후 재해형태 집계가 갱신되는가 (대시보드 재해형태 통계 확인 가능하면)

> `executeSumOfDisasterForm`(집계)은 **유지**, `trscSimilarWord`(유사어 학습)만 삭제.
> 삭제분: `wdlCont_DisasterForm` 콜백 블록 전체 + `DIV_CD`/`SML_SEQ`/`KEEP_NM` 선언 + Mapper·ServiceImpl 호출
> 관련: `#{REG_SN}` / `#{REG_DTL_SN}` 바인드로 변경된 PL/SQL

### 4-2. 접수 / 접수취소 (레거시 경로, 옵션060_003=F)

- [ ] 접수 → 상태 변경
- [ ] 접수취소 → 상태 복귀
- [ ] **푸시 알림** 발송 확인 (가능하면)

> 관련: `mPayload.put("regSn", amWdmAssmnt.get("REG_SN"))` — 좌변은 외부 API 필드라 유지

## 8. 실패 시 대응

| 증상 | 유력 원인 | 확인 위치 |
|---|---|---|
| `ORA-00904: invalid identifier` | 인라인뷰/CTE 별칭 참조 불일치 | 해당 쿼리의 `x.OLD` ↔ 안쪽 별칭 |
| 팝업에서 값 골랐는데 그리드 그대로 | 외부 계약 키 오치환 | `aoRtnDat.data.*` (원복분) |
| 팝업이 빈 데이터로 뜸 | 팝업 파라미터명 불일치 | `openPopup` 의 `oData` 좌변 |
| 저장은 되는데 조회하면 없음 | PK 바인드 null | `#{REG_SN}` ↔ FE 세팅 키 |
| 승인 액션 후 상태 미반영 | 승인 핸들러 키 불일치 | `oSanctnKeys` ↔ `SfasAtRiskasmtSanctionHandler` |
| 컬럼이 빈칸(에러 없음) | 쿼리 출력명 ↔ dataList 선언 불일치 | 해당 쿼리 최상위 Select 별칭 |

> 롤백이 필요하면 배치 단위로 되돌릴 수 있게 **커밋을 4개로 분리**할 예정입니다.
> (배치1 / 배치2+승인핸들러 / 죽은출력 정리 / 팝업 미사용 컬럼)
