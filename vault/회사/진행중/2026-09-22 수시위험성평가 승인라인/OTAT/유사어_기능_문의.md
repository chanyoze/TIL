# 재해형태 유사어(동의어) 자동학습 기능 문의

> 작성: 2026-08-05 / 상시·수시위험성평가서접수 화면 리팩토링 중 발견
> 요청: 2024년 상반기 유사어 정책 변경 여부 확인

---

## 0. 요약 (평문)

재해형태는 자유 입력이라 "추락", "떨어짐(추락)" 처럼 표기가 제각각이고, 이를 묶어 통계를 합산하는 **유사어 사전**이 있습니다. 사용자가 검색어를 입력해 항목을 고르면 그 검색어를 동의어로 자동 등록하는 기능이 있었는데, **2024년 4월 29일 이후 완전히 멈췄습니다**(그전까지 94개 회사·약 5천 건 등록). 관리자 수동 등록도 2024년 7월에 같이 멈췄습니다.

원인은 위험성평가 계열 화면 4개에서 **검색어 원문을 기억하는 설정 2줄이 빠진 것**입니다. CCMS 재해사례 화면은 그 설정이 남아 있어 지금도 정상입니다. 언제 빠졌는지는 추적이 안 됩니다 — Git이 2025년 3월 SVN 이관 시점 하나만 갖고 있는데 그때 이미 없었습니다.

**여쭙고 싶은 건 이게 의도적으로 중단한 것인지**입니다. 자동·수동 등록이 2024년 상반기에 나란히 멈춰서, 관리 방침이 바뀐 것처럼도 보입니다.

되살리는 건 설정 2줄이면 되지만, **2년 3개월 공백이 걸립니다.** 지금 켜도 신규만 학습되고 그사이 따로 등록된 건 그대로라 통계가 어긋난 채 이어집니다. 다만 공백기 신규가 667건(전체의 1.5%)이라 실익이 크지 않을 수도 있습니다. **재해형태 통계가 이상하다는 얘기가 나온 적 있는지** 알려주시면 판단하겠습니다. 그때까지 관련 코드는 지우지 않고 두겠습니다.

---

## 1. 확인하고 싶은 것

**재해형태 유사어 자동학습(`DIV_CD='ADD'` 경로)이 2024년 4월경 의도적으로 중단된 것인지**, 아니면 다른 작업 중 유실된 것인지 확인 부탁드립니다.

---

## 2. 이 기능이 하던 일

재해형태는 자유 텍스트라 같은 재해도 표기가 제각각입니다. 이를 하나의 `SML_SEQ`로 묶어 통계를 합산하는 정규화 사전이 유사어 기능입니다.

```
"떨어짐(추락)"  ┐
"추락"          ├─→ SML_SEQ 1234 ─→ 대시보드 재해형태 통계에서 합산
"낙하·비래"     ┘
```

- `TCC_SIMILAR_WORD` — 대표어 마스터 (`SML_SEQ` 채번)
- `TCC_SIMILAR_WORD_DETAIL` — 대표어에 딸린 **동의어 목록**
- `TSF_ASSMNT_RECEIVE_DR` — 평가서 상세별 `SML_SEQ` 집계
- 대시보드 4종(경남·동문·금성백조·한국농어촌공사)이 재해형태 통계에 사용

평가서 저장 시 `executeSumOfDisasterForm` 이 재해형태를 분해해 마스터·동의어 양쪽에서 `SML_SEQ`를 찾고, 못 찾으면 마스터에 신규 등록합니다.

## 3. 멈춘 지점

`trscSimilarWord` 는 `DIV_CD` 로 3분기합니다.

| `DIV_CD` | 동작 | 대상 | 현재 |
|---|---|---|---|
| `NEW` | 신규 재해형태를 마스터에 등록 | `TCC_SIMILAR_WORD` | 정상 |
| `CLOSE` | 취소 시에도 마스터 등록 | `TCC_SIMILAR_WORD` | 정상 |
| **`ADD`** | LOV 검색어를 선택한 대표어의 **동의어로 자동 등록** | `TCC_SIMILAR_WORD_DETAIL` (`REG_CD='B'`) | **동작 안 함** |

### 원인 — 화면 LOV 옵션 2개 누락

`ADD` 는 사용자가 LOV에 입력한 **원본 검색어**가 `KEEP_NM` 컬럼에 남아 있어야 발동합니다. 그 값을 남기는 건 LOV 옵션입니다.

```js
// 동작하는 화면 — CcmsRegAcdtcSst
sInColMap: "DR_FORM_SN=SML_SEQ, DISASTER_FORM=DISASTER_FORM",
bMultiple: true,
bKeepKeyIn: true,                          // 입력값 보존
sKeepKeyInAfterChoiceColId: "KEEP_NM"      // 보존값을 넣을 컬럼

// 동작 안 하는 화면 — SfasRegAtRiskasmtRcpt 외 3종
sInColMap: "DISASTER_FORM=DR_FORM, DR_FORM_SN=SN",
bMultiple: true
// bKeepKeyIn / sKeepKeyInAfterChoiceColId 없음
```

`KEEP_NM` 이 채워지지 않으므로 아래 분기가 도달 불가이고, `DIV_CD` 가 `'ADD'` 로 세팅되는 경로 자체가 사라집니다.

```js
if(!cips.util.isEmpty(wdlCont.getCellData(..., "KEEP_NM"))) {
    wdlCont.setCellData(..., "DIV_CD", "ADD");   // 실행 안 됨
}
```

### 영향 화면

| 화면 | `bKeepKeyIn` | `ADD` 학습 |
|---|---|---|
| `CcmsRegAcdtcSst` (CCMS 재해사례) | 있음 | 동작 |
| `SfasPopRegFirstDngrApplyAll` | 있음 | 동작 |
| `SfasRegAtRiskasmtRcpt` (수시 접수) | **없음** | **중단** |
| `SfasRegAtRiskasmtSub` (수시 제출) | **없음** | **중단** |
| `SfasRegFirstDngrProjType2` | **없음** | **중단** |
| `SfasRegFirstDngrRcompanyType2` | **없음** | **중단** |

위험성평가 계열 4개 화면만 옵션이 빠져 있습니다.

## 5. 시점 정리

| 시점 | 사건 |
|---|---|
| 2022-07 ~ 2024-04 | `ADD` 자동학습 정상 동작 (`REG_CD='B'` 4,966건 누적) |
| **2024-04-29** | **`ADD` 마지막 등록 — 이후 0건** |
| 2024-07-04 | 관리화면 수동 등록(`REG_CD='A'`)도 중단 |
| 2025-03-13 | SVN → Git 이관. **이관 스냅샷에 이미 `bKeepKeyIn` 없음** |
| 2026-02-19 | 검토의견 개편(`f36086f45`) — 새 이력 데이터셋에 죽은 컬럼 구성을 복제 |

Git 이력은 SVN 이관(2025-03-13) 스냅샷 1개부터 시작해 그 이전을 추적할 수 없습니다. 다만 **`bKeepKeyIn` 은 Git 전 기간 이 파일에 단 한 번도 존재한 적이 없어**, 이관 이전에 이미 제거·유실된 상태였음이 확실합니다.

**동의어(`A`)와 자동학습(`B`)이 2024년 상반기에 나란히 멈춘 점**으로 보아 그 무렵 유사어 관리 정책 자체가 바뀌었을 가능성이 있어 문의드립니다.

## 6. 질문

1. 2024년 상반기에 유사어(재해형태 동의어) 관리를 **의도적으로 중단**한 이력이 있습니까?
2. 중단이 아니라면, `bKeepKeyIn` 옵션 제거가 어떤 작업의 부수효과였는지 기억나시는지요?
3. 재해형태 통계(대시보드 4종)에서 동의어 미학습으로 인한 **집계 분산 이슈가 보고된 적**이 있습니까?
4. 지금 복구하는 것이 맞습니까? 아래 판단이 필요합니다.

### 복구 시 고려사항

- **기술적으로는 LOV 옵션 2줄 추가**면 됩니다. 동작하는 레퍼런스(`CcmsRegAcdtcSst`)가 살아 있습니다.
- 다만 **2년 3개월의 공백**이 있어, 지금 켜면 **신규 입력분만 학습**되고 그 사이 분산 등록된 항목은 그대로 남습니다 → 통계 연속성이 끊긴 구간이 생깁니다.
- 소급 정리하려면 **별도 데이터 마이그레이션**(기존 마스터 항목 간 동의어 병합)이 필요합니다.
- 중단 이후 마스터 신규가 667건에 그쳐 **분산 규모 자체는 크지 않아**, 복구 실익이 낮을 수도 있습니다.

## 7. 현재 조치

- 관련 컬럼(`SML_SEQ`·`KEEP_NM`·`DIV_CD`) 및 JS 분기는 **삭제하지 않고 보류**했습니다. 지금 지우면 복구 시 4개 화면을 다시 손봐야 하기 때문입니다.
- 진행 중인 단어사전 리네임 작업에서도 이 컬럼들은 **손대지 않았습니다.**
