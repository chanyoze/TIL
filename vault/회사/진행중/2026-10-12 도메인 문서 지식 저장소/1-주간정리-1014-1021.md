도메인 분석 문서는 **다른 도메인을 맡은 개발자가 이 도메인의 화면 · 테이블을 건드리기 전에 먼저 읽는 문서**다. 사실(표)은 스크립트가 소스에서 뽑고, 흐름 설명은 AI 가 코드를 읽고 쓴다. 이 작업을 `domain-doc` 스킬로 묶어 도메인마다 돌리고 있다.

10월 14일에 중간 발표를 했다. 이 글은 그 뒤 일주일 동안 **무엇이 바뀌었고, 무엇을 거뒀고, 다음 주에 무엇을 할지**를 다음 발표 자료의 원천으로 남겨 둔 것이다.

## 출발점 — 10-14 발표 때

| 도메인 | 상태 |
|---|---|
| FIFT (최초 · 정기 위험성평가) | 화면 시험(4단계) 92개 중 88개, 정확도 평가 오답 0 |
| TBM A / B | A 오답 0, B 오답 2 (원인은 둘 다 자동 생성 표) |
| OTAT (상시 · 수시 위험성평가) | 옛 양식 문서, 평가 기록 없음 |

그때 남은 과제는 생성 표 오류, 다른 화면 SQL 이 섞이는 문제, 스킬 개선 요청 11건, FIFT 5 · 6 · 8단계였고, 정할 것이 다섯 가지(둘째 전용 현장, 결함 후보, OTAT 새 양식 전환, 평가 범위, 피드백 착수 시점) 있었다.

> 용어 — **4단계**는 떠 있는 서버의 화면을 실제로 눌러 목업 데이터를 만들고 캡처하는 단계, **8단계**는 문서만 읽은 에이전트에게 소스에서 뽑은 질문을 던져 답이 맞는지 채점하는 단계다.

## 일주일 동안 스킬이 바뀐 것

- **10-15 문서 구조** — 문서 원본을 부(部)별 파일로 나누고 합본은 생성물로 돌렸다. 테이블 부는 ERD 에서 생성, 점검 사항은 별도 부. HTML 폭 검사(`layout.js`), 바뀐 화면만 다시 찍는 `capture.js --changed`. 신입 개발자 피드백을 반영했다.
- **10-16 분석기 보강** — 모바일 서비스 · 계산 칸 · Insert 값까지 읽게 했고, 호출 색인(`callindex.js`)으로 "밖에서 이 메서드를 부르는 길"을 찾게 했다. 결함 후보 양식, 평가 부분 정답 집계, 대시보드 부도 이날 들어갔다.
- **10-16 FIFT 전면 복기** — 평가는 오답 0 이었는데, 서술을 소스와 하나하나 대조하는 **사실 감사**를 돌리자 118건 중 16건이 틀렸다. 비교 서술 · 점검 판정은 평가 문항이 건드리지 못했던 것. 감사를 절차에 넣었다.
- **10-19 역할별 에이전트 7개** — 서술 작성(2종) · 출제 · 답변 · 보조 답변 · 채점 · 감사를 각각 다른 모델과 권한으로 나눴다. 생성 표 결함 4건을 고치고 4개 도메인 표를 다시 생성했다.
- **10-20 4단계 도구** — MEET 에서 막혔던 7가지를 도구로: 시나리오 뼈대 생성, "닿지 않을 후보" 표시, 선택 창 · 서버 차단 · 상태 읽기 함수, 실패 시 화면 상태 기록, 단계별 시간 기록.
  - 알게 된 것: 그리드 칸의 선택 창은 **클릭으로는 안 열리고 값을 고쳐야** 열린다(`onafteredit` 에서만 연다).
- **10-20 DB 접근 표준** — AI 의 DB 접근을 **SQLcl + 조회 전용 계정 하나**로 통일했다. 규칙만 적는 대신 전역 훅이 다른 접속 · 셸 DB 클라이언트를 막는다. 설정 파일에 평문 비밀번호가 있던 예전 MCP 는 지웠다.
  - 함정: 컴퓨터 이름과 사용자 이름이 같으면 Java 가 사용자를 컴퓨터 계정으로 풀어 SQLcl 의 접속 저장이 실패한다. 실행 옵션으로 사용자 이름을 명시해 풀었다.
- **10-20 정리** — 집 · 회사 스킬 동기화 저장소는 마켓플레이스 등재로 대체하기로 하고 폐기. 안에 있던 개발표준 동기화 스크립트는 스킬 저장소로 옮겼다.

## 금주 성과

| 도메인 | 한 일 | 시간 · 토큰 | 8단계 평가 | 4단계 |
|---|---|---|---|---|
| FIFT | 재구성 완료 | 여러 세션 | 42문항 정답 38 · 부분 4 · **오답 0** | 기존 |
| OTAT | 새 양식으로 처음부터 재구성 | 62분 · 약 230만 | 20문항 정답 15 · 부분 5 · **오답 0** | 3시간 29분 · 27.5만, 43단계 실패 0 |
| MEET (회의록) | 새로 작성 — 역할별 에이전트 첫 적용 | 누적 약 5시간 20분 · 약 435만 | 20문항 정답 10 · 부분 10 · **오답 0** | 3.5시간 · 48.7만 |

- 근거 대조(문서의 출처 표기가 소스와 맞는지)는 OTAT 318/318, MEET 232/232.
- MEET 전수 감사 208블록: Opus 가 쓴 부 10%, Sonnet 이 쓴 부 13% 가 틀리거나 넓었다 — **모델 차이는 없었다.** 22건을 문서에 반영.
- 모델 나눠 쓰기의 결과: 토큰은 줄지 않았고 비용만 약 13% 줄었다. 품질 차이는 없었다. 효과는 도메인을 더 해 보고 다시 판단한다.
- 결함 후보: MEET 16건, OTAT 14건을 담당자 확인용으로 모았다.
- 10-14 의 미결 → OTAT 새 양식 전환 완료, 생성 표 오류 수정, 스킬 요청 일괄 반영.

## 배운 것

1. **평가 오답 0 ≠ 정확한 문서.** 감사를 따로 돌리면 매번 약 10% 가 틀리거나 넓었다. 끝났다는 기준은 "평가 + 감사"다.
2. **화면을 눌러 봐야만 나오는 사실이 꼭 있다.** 예: 날짜 자동 맞춤, 참석은 사람별, 공통 필수 검사가 화면 검사보다 먼저 돈다.
3. **4단계가 가장 비싸다.** OTAT 3시간 29분 중 66% 가 브라우저를 기다린 시간이었다. 새 도구로 토큰은 44% 줄었지만 시간은 그대로였다.
4. **도메인마다 같은 창을 다시 풀고 있었다.** MEET 에서 푼 "기본모델가져오기" 창을 OTAT 가 다시 푸느라 28분 · 실패 7회를 썼다.
5. **실수도 장치로 막았다.** 저장으로 날짜 검사를 확인하다 관리기간을 하루짜리로 만든 일(전용 현장이라 되돌림), 문자열 치환 특수문자로 백로그가 깨진 일 — 모두 절차서와 검사에 막는 장치를 넣었다.
6. 스킬은 세 번째 도메인에서야 안정된 느낌이다. 다음 도메인은 **스킬을 고치지 않고 끝까지 도는지**가 시험이다.

## 4단계를 빠르게 — 가능성 확인

| 방안 | 내용 | 확인 결과 |
|---|---|---|
| A | 떠 있는 브라우저에 붙었다 떨어지며 시험 | 시험 완료 — 첫 로그인 35초, 다시 붙기 0.4초, 화면 상태 유지 |
| B | 고정 대기 → 조건 대기 | 실측 — 메뉴 열기 · 조회 · 줄 고르기 시간의 77~98% 가 고정 대기 |
| C | 빨리 실패하고, 실패한 단계부터 이어서 | 간단 — OTAT 에서 5분 초과 3회(15분) 대상 |
| D | 화면 필수 조건을 시나리오 뼈대에 미리 | 일부 가능 — 결재자 미지정 연쇄 실패 7회 대상 |

여기에 **공통 동작**을 더한다. 여러 도메인이 같이 여는 창 — 기본모델 · 발생항목 · 평가모델 가져오기, 제출 · 승인 처리와 취소 의견 창, 라인추가 · 일괄 처리 — 을 한 번 풀어 두고 모든 도메인이 가져다 쓰게 한다. 목표는 같은 도메인 기준 1~1.5시간대(추정, 실측 전). 개선 방향은 스킬 백로그에 기록해 두었다.

## 다음 주 계획

1. 4단계 속도 개선 구현 — B+C → 공통 동작 → A → D 순서.
2. 다음 새 도메인(중점점검활동)으로 측정 — OTAT 를 다시 돌리지 않고 새 도메인에서 효과를 본다. 화면 수 · 단계 수 · 실패 수와 원인 · 대기 대 작성 비율을 남긴다.
3. OTAT 마무리 — 화면에서 확인한 사실을 문서에 반영하고 HTML 재생성.
4. 담당자 확인 받기 — 메뉴 구분자(4자리 표준, 150번까지 우선 요청함), 옵션 이름, 미사용 팝업, 결함 후보.
5. 마켓플레이스 등재 준비 — 스킬 + DB 접근 설정을 함께 묶는다(설정에 비밀번호가 없어져서 가능해졌다).
6. 쌓인 변경 커밋 정리. 회의록 문서는 메뉴 구분자가 정해질 때까지 올리지 않는다.

## 발표 자료에 쓸 만한 것

- 10-14 → 10-21 도메인 상태표 비교
- "오답 0 인데 10% 가 틀렸다" — 평가와 감사는 다른 것을 잡는다
- 4단계 시간 분해(브라우저 대기 66%) → A~D + 공통 동작
- 도메인 하나의 비용(첫 작성 약 400만 토큰 · 5시간대)과 목표치
- DB 접근을 규칙이 아니라 권한과 훅으로 막은 것
